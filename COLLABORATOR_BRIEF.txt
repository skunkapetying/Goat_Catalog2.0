==================================================
1. WHAT THIS PROJECT IS
==================================================

This project is a public-facing website for listing and searching goat genetics.

In simple terms:

- People use the site to look up bucks (male goats)
- Each buck can have a public listing
- The listing helps people review basic information about that buck's genetics
- The site is focused on goat breeding and semen/genetics marketing

This is not a general farm website and it is not a pet goat website.

The site is specifically about breeding-related catalog information.


==================================================
2. VERY BASIC GOAT TERMINOLOGY
==================================================

This section is for collaborators who have no livestock background.

Buck:
- A male goat

Doe:
- A female goat

Sire:
- The father of an animal
- If a listing says "sire," it means the buck's father

Dam:
- The mother of an animal
- If a listing says "dam," it means the buck's mother

Lineage:
- Family background
- In this project, it mainly means sire, dam, color, FullBlood, and enoblement

Breed:
- The type of goat
- Example breeds include Boer, Nubian, Alpine, LaMancha, and Oberhasli

Boer:
- A meat-goat breed
- Many of the current listings are Boer-related

Dairy breeds:
- Goat breeds primarily associated with milk production
- These may be added more heavily later

Registration number:
- An official identification number assigned by a breed association or registry

Association:
- The breed registry or organization tied to the listing
- Example: ABGA

ABGA:
- American Boer Goat Association
- This mainly applies to Boer goats

Enoblement:
- A formal recognition/status used in Boer-goat contexts
- In practice, this field may contain text like "*ENNOBLED*" or points-related wording

FullBlood / Percentage:
- A way of describing how fully an animal belongs to a registered bloodline category
- In this project, the field name is "fullBlood" even though the value may be "Full Blooded" or "Percentage"

Slug:
- The URL-safe version of a listing name
- Example:
  buck name: Cedar Ridge Archer
  slug: cedar-ridge-archer

==================================================

The website currently does three main things:

1. It shows a public catalog of active listings

3. It provides an individual details page for each listed buck

The public catalog should only show listings marked as active.

Current searchable fields include:

- buck name
- registration number
- sire
- dam
- color

Current filter categories include:

- breed
- association
- enoblement
- FullBlood

5. MAIN PROJECT GOAL
==================================================

The main goal is:

Build a clean, searchable, public genetics catalog that is easy to maintain and easy to enter data into.

That goal has two parts:

A. Public-facing goal

B. Internal maintenance goal
- The data structure should stay simple enough that humans can actually manage it in Grist without frustration


==================================================
6. WHY THE PROJECT WAS RECENTLY REFACTORED
==================================================

Earlier in development, the data model was getting too wide and too cluttered.

The big issue was that too many unrelated fields were being pushed into one general-purpose structure. That made Grist data entry harder because users had to scroll too far left and right to work with records.

To reduce that complexity, the project was narrowed down.

The current direction is:

- one table for listing information
- one table for lineage information

That means the project is now trying to separate:

"What is this listing?"
from
"What family/genetic information belongs to this listing?"

7. CURRENT ACTIVE DATA MODEL
==================================================

The project currently uses two live CSV files as the active data model.

These files are:

- GRIST_LISTINGS.csv
- GRIST_LINEAGE.csv

There are also schema guide files:

- GRIST_SCHEMA_LISTINGS.csv
- GRIST_SCHEMA_LINEAGE.csv


--------------------------------------------------
7A. GRIST_LISTINGS.csv
--------------------------------------------------

This file stores listing-level information.

Fields:

- listingId
- slug
- buckName
- registrationNumber
- breed
- association
- status
- sortOrder
- createdAt
- updatedAt

What this file answers:

- What is the listing called?
- What breed is it?
- What registration number belongs to it?
- What URL slug should it use?
- Should it appear in the public catalog?


--------------------------------------------------
7B. GRIST_LINEAGE.csv
--------------------------------------------------

This file stores lineage-level information.

Fields:

- listingId
- color
- fullBlood
- enoblement
- sire
- dam

What this file answers:

- What color is the buck?
- Is it Full Blooded or Percentage?
- What enoblement-related text belongs to it?
- Who is the sire?
- Who is the dam?


--------------------------------------------------
7C. HOW THE FILES CONNECT
--------------------------------------------------

The key connection field is:

- listingId

That means each lineage row belongs to a listing row with the same listingId.

Example:

- Listings row:
  listingId = buck-019

- Lineage row:
  listingId = buck-019

Those two rows describe the same public buck listing.

18. DETAILED DESCRIPTION OF THE PROJECT
==================================================

This project is a practical web catalog for goat breeding and genetics listings. Its main purpose is to let users browse and search public buck listings, with an emphasis on lineage and breeding-relevant information rather than general farm storytelling or media-heavy presentation.

The project is unusual because it sits between livestock recordkeeping and public-facing web design. On one side, it needs to reflect real breeding-related information such as registration numbers, sire, dam, breed, association, and lineage categories. On the other side, it has to remain understandable and easy to update for humans who are entering and maintaining the data.

One of the central lessons so far has been that too much flexibility too early creates maintenance problems. When too many fields were included in one broad schema, the Grist workflow became awkward and inefficient. That led to a deliberate simplification effort. Instead of trying to manage listing identity, media, notes, pedigree summaries, seller contact, registry extras, and lineage all at once, the project was narrowed down to the information most necessary for the catalog's current job.

That narrowed structure now centers on two categories:

- Listings
- Lineage

This split is important because it lets the project grow without becoming unreadable. Listing data describes the public listing itself. Lineage data describes the genetics-related details of that listing. This is a much better fit for both manual data entry and future development.

The project is also preparing for a broader future. Although much of the current work is Boer-oriented, especially where ABGA is involved, the site is expected to expand into dairy breeds and more associations over time. The schema now makes room for that future without pretending all of those details are already fully known.

In practical terms, this means the project is trying to be disciplined. It is not chasing every possible feature. It is trying to become a stable, searchable, easy-to-maintain genetics catalog with a clean enough internal structure that the team can keep building on it without creating another round of data chaos.
